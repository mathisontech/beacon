## Overview

The People & Community module encompasses all user account management, group coordination, peer-to-peer mutual aid, and animal rescue operations within Beacon. It serves as the central hub for individual users, communities, and inter-organizational coordination during emergencies and daily operations.

**Strategic Goals:**
- Enable users to manage identities, verify credentials, and control location sharing
- Facilitate coordinated evacuation via groups (neighborhood, school, burn-together, convoy)
- Provide peer-to-peer mutual aid matching (transport, evacuation confirmation, resources, responder assistance)
- Support animal rescue coordination with community-wide visibility
- Integrate with EMS/government agencies for verified community leadership roles

**Mission Alignment:** Saves lives through verified community coordination, trusted-neighbor networks, and collective resource pooling during disasters.

## Sub-Modules

### 1. Public User Account Manager

**Purpose:** Manage complete user account lifecycle, identity verification, and personal settings.

**Key Features:**
- **Account Registration & Profile:** Name, email, phone, profile photo, forward-facing verification photo
- **ID Verification:**
  - Face match (biometric selfie vs. ID document)
  - Background checks (integration with provider)
  - Sex offender registry lookup (periodic automated re-checks)
- **Emergency Contacts:** Import, invite to Beacon, designate next-of-kin, link dependents
- **Vehicle Manager:** NHTSA vPIC lookup for make/model specs, manual fallback with silhouette selection, special capabilities (snow tires, 4WD, undercarriage clearance)
- **Disability & Household Info:** Elderly status, children count, animals, accessibility needs
- **Trusted Neighbors:** Request/designate verified contacts for emergency assistance
- **Location Sharing Controls:** 4 modes (off, group-only, emergency-only, public) × 4 granularity levels (exact ±50m, neighborhood-block ±200m, neighborhood ±500m, city ±5km)
- **Notification & Alert Preferences:** Hazard type subscriptions, delivery method selection, frequency controls
- **Equipment & Skills Registration:** Snow plow, excavator, boat access, swimming ability, rescue certifications

**Inputs:**
- User registration form (email, phone, photo)
- ID verification documents (driver's license, passport)
- Vehicle make/model/year selection
- Disability/household declaration
- Location sharing preferences
- Background check results (async from third-party provider)

**Outputs:**
- User account record
- Verification status (unverified, verified, flagged)
- Device trust status (location enabled, notifications enabled)
- Trusted neighbor invitations sent

### 2. Groups Manager

**Purpose:** Create, manage, and coordinate four distinct group types for geographic, educational, burn coordination, and evacuation use cases.

**Group Types:**

#### 2.1 Neighborhood Groups
- Geographic clusters (50-500 households)
- Membership discovery-based
- Founder becomes default admin, can transfer
- Admin privileges: add/remove members, set policies, manage messaging channels, delete if ≤20 members and inactive >90 days

#### 2.2 Parent-Community Groups
- Auto-spawned via school partnerships
- Principal receives admin invite, gets real-time student location during events
- Membership verified via email domain or principal approval
- Channels: emergency updates, daily weather, evacuation status, resource requests

#### 2.3 Burn-Together Groups
- AI-calculated auto-membership based on wind direction, fuel type, proximity (5-mile radius), insurance tier
- Fire chief/coordinator oversees, manually adjustable
- Time-limited: dissolves after burn completion or 180 days

#### 2.4 Evacuation Convoy Groups
- Temporary, auto-generated by evacuation system
- Role-assigned (driver, passenger, leader)
- Vehicle capacity tracked
- Departure/arrival reporting to EMS

**Admin Hierarchy:**
- Founder: Create, set policies, transfer ownership
- Admin: All founder permissions except transfer, manage sub-admins
- Moderator: Remove members/messages, pin announcements, no policy changes
- Member: View directory, message, update location settings

**Privacy Controls:**
- Location sharing: Off, group-only (encrypted), emergency-only, periodic check-in
- Granularity per-user per-group: exact, neighborhood-block, neighborhood, city
- Audit trail: Members see who accessed their location, timestamps
- 72-hour retention for group members, 30 days for EMS emergency context

**Evacuation Coordination:**
- Group enters "event mode" on alert trigger
- Displays: zone overlay, shelter assignments, convoy roster, capacity
- Members: join convoy, confirm evacuation status, report vulnerable needing help
- Admins: see real-time departure, arrival, unaccounted members (push escalation if >30 min non-responsive)

### 3. People Helping People Manager

**Purpose:** Coordinate peer-to-peer mutual aid with EMS integration for volunteer matching and safety protocols.

**Six Help Categories:**

#### 3.1 Transport & Evacuation
- User requests evacuation ride
- System matches with nearby verified users who've offered transport
- Shared location for pickup coordination
- EMS visibility for liability tracking

#### 3.2 Evacuation Confirmation
- EMS geofences area, asks volunteers to verify buildings are empty
- Photo evidence collected
- Confirmation feed visible to EMS (prioritizes areas)

#### 3.3 Condition Reporting
- EMS requests area-specific observations (fire color/smoke, flood depth, road conditions)
- Geofenced push to users in area
- Photo + text submissions
- Feeds into hazard model validation

#### 3.4 Resource Lending
- EMS/police request specific equipment (excavator, boat, ATV, snowmobile)
- Users with equipment registered in profile are matched
- Per-request opt-in (not blanket sharing)
- Example: Buffalo PD requests ATV during blizzard

#### 3.5 Responder Assistance
- First responder in distress requests shelter, supplies, or evacuation help
- Higher priority than public requests
- Automatic location sharing for 2 hours with responder

#### 3.6 Suspect/Missing Person Photos
- Police crowd-source photos for suspect identification or Amber Alert
- Geofenced request to nearby users
- Legal review required before deployment (kill switch pending)

**Matching Algorithm:**
- Proximity-based (5km default radius, expandable)
- Capability matching (vehicle type, equipment, certifications)
- Vetting status (background check, trusted neighbor designation)
- Availability (user marked "willing to help" in settings)
- Safety scoring (response time history, complaint rate)

**Safety Protocols:**
- Liability waiver on first help offer
- Good Samaritan protection disclosure
- Emergency responder oversight (EMS sees all public requests)
- Kill switch: EMS/admin can shut down request broadcast immediately
- Optional anonymous mode for requester
- Auto-expiration: requests timeout 2-4 hours if not accepted

### 4. Animal Rescue Manager

**Purpose:** Track lost/found animals and coordinate volunteer rescue during emergencies and daily operations.

**Core Features:**
- **Lost/Found Reporting:**
  - Pet photo, species, breed, distinguishing features
  - Home location (if lost from home during evacuation)
  - Shelter location (if found/rescued)
  - Contact info for owner
  - Photo matching (AI-assisted breed/appearance matching across reports)

- **Rescue Workflow:**
  - Owner: Clicks home on map, reports "pet at home, need rescue"
  - Includes: animal description, hide-a-key location, access instructions
  - Nearby verified users alerted (5km radius, expandable)
  - Responder: Offers to help, location auto-shares for 4 hours
  - Owner accepts: Messaging opens for detailed coordination
  - System tracks: rescue attempt status, animal confirmed safe, current location

- **Shelter Capacity Management:**
  - Shelter registration with pet-friendly status
  - Real-time occupancy tracking
  - Accepting/full status toggle
  - Medical capability (vaccines, quarantine, specialized care)
  - Volunteer coordinator contact

- **Veterinary Resources:**
  - Vet clinic locations and capacity
  - Telemedicine consultations for behavioral/medical assessment
  - Supply lending (carriers, food, medications)

- **Reunification Workflows:**
  - Animal ID tracking (microchip lookup, photo match)
  - Owner notification when animal located
  - Safe transfer logistics (meeting point, time, responder ID)
  - Post-event follow-up (welfare check in days following)

```

├── Public User Account Manager (Sub-module 1)

└── Animal Rescue Manager (Sub-module 4)

External Integrations:
├── Account & Auth (43) → User authentication, role permissions
├── Location Sharing (44) → Granularity controls, privacy enforcement
├── Notification System → Alert delivery, channels
├── EMS Admin (42) → Help request visibility, evacuation coordination
├── Vehicle Manager (16) → Vehicle specs, user vehicle profiles
├── Hazard Models → Condition reporting validation
└── Third-Party APIs:
    ├── NHTSA vPIC → Vehicle specs lookup
    ├── Background check provider → ID verification
    ├── Microchip registry → Animal reunification
    └── Utilities/Telecom → Emergency contact validation
```

### User Roles & Access Control

**Public Users:**
- Register, manage profile, join groups, offer/request help
- Create animal rescue requests
- No EMS data visibility

**Group Admins/Moderators:**
- Full group management (members, channels, policies)
- View member evacuation status during events
- Broadcast announcements

**EMS/Government Designations (Special):**
- School Principal: Student location access, evacuation coordination
- Utility Rep: Infrastructure/outage visibility, public notification
- Plower: Road condition updates, work order dispatch
- Tornado Tracker: NWS integration, image submission
- Fire Chief: Evacuation orders, mutual aid, strike team management
- EMS Director: Hospital capacity, ambulance dispatch
- State Emergency Rep: Statewide evacuation recommendations
- State Politician: Constituent communication
- Federal Representative: Interstate coordination
- Hospital Rep: Patient surge, mutual aid requests

**Beacon Employees:**
- Super Admin: All layers, all versions, user management
- Account Manager: Client setup, usage stats, special designation verification
- Content Moderator: Story/photo review, help request validation

## Database Schema

### Core Tables (PostgreSQL + PostGIS)

#### users
```sql
CREATE TABLE users (
  id BIGSERIAL PRIMARY KEY,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  email VARCHAR(255) UNIQUE NOT NULL,
  phone_number VARCHAR(20),
  display_name VARCHAR(255),
  profile_photo_ref VARCHAR(500),
  id_verified_at TIMESTAMP WITH TIME ZONE,
  id_verification_status VARCHAR(20), -- unverified, verified, flagged
  sex_offender_check_status VARCHAR(20), -- pending, clear, flagged
  sex_offender_last_checked TIMESTAMP WITH TIME ZONE,
  disabled BOOLEAN DEFAULT FALSE,
  disability_notes TEXT,
  children_count INT,
  animals_count INT,
  default_vehicle_id BIGINT REFERENCES vehicles(id),
  location_share_default_granularity VARCHAR(20),
  battery_level_share_enabled BOOLEAN DEFAULT FALSE,
  emergency_contacts JSONB, -- [{id, name, email, phone, relationship, invited}, ...]
  next_of_kin_id BIGINT REFERENCES users(id),
  trusted_neighbors JSONB, -- [{id, vetting_status, authority_level}, ...]
  equipment_skills JSONB, -- [{type, quantity, photo_ref}, ...]
  retired_emergency_personnel VARCHAR(100), -- fire, police, ems, cert, plower
  retired_personnel_verified_at TIMESTAMP WITH TIME ZONE
);

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_phone ON users(phone_number);
CREATE INDEX idx_users_id_verified ON users(id_verified_at DESC);
```

#### vehicles
```sql
CREATE TABLE vehicles (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,

  model VARCHAR(100),
  year INT,
  length_cm INT,
  width_cm INT,
  height_cm INT,
  curb_weight_kg INT,
  turn_radius_m DECIMAL(5,2),
  undercarriage_clearance_cm INT,

  towing_capacity_kg INT,
  has_snow_tires BOOLEAN DEFAULT FALSE,
  has_chains BOOLEAN DEFAULT FALSE,

  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),

CREATE INDEX idx_vehicles_user ON vehicles(user_id);
```

## Consideration Framework

### 1. Product & Strategy

#### Market Positioning
- Beacon serves communities of all sizes (small towns to metro areas)
- Dual-track rollout: free public version + EMS-integrated premium
- Competitive advantage: offline-first mesh network + verified community leaders
- Target 1M+ active users within 18 months of EMS partnerships

#### User Personas
- **Individual Users:** Age 18-75, smartphone-equipped, seeking community connection and emergency resilience
- **Group Leaders:** Age 30-65, community organizers, school principals, neighborhood watch coordinators
- **EMS/Government:** Full-time emergency professionals, part-time volunteers, administrative staff
- **Elderly/Vulnerable:** Mobility limitations, may not have smartphone, rely on trusted neighbors, family

#### Product Goals
- **Adoption:** Easy account setup (<2 min), visible value from day 1
- **Engagement:** 30% monthly active users in group-enabled regions
- **Safety:** Zero false positives on critical requests (100% precision required)
- **Trust:** Transparent vetting, clear liability boundaries, Good Samaritan protection

---

### 2. Technical Architecture

#### Technology Stack
- **Backend:** Node.js/Express (API), Go (geofencing, routing), Python (ML, data pipelines)
- **Database:** PostgreSQL + PostGIS (relational, geospatial), TimescaleDB (time-series), Elasticsearch (message search), Redis (caching, sessions)
- **Mobile:** React Native (cross-platform), native modules for location/camera
- **Infrastructure:** Kubernetes on AWS, CloudFront CDN, NATS message broker
- **Encryption:** TLS 1.3 in-transit, AES-256-GCM at-rest, ECDH for mesh

#### Microservices Boundaries
```
User Account Service → Vehicle Lookup, ID Verification, Contact Manager
Groups Service → Channel Messaging, Member Management, Location Sharing
Help Request Service → Geofencing, Matching Engine, Responder Tracking
Animal Rescue Service → Photo Matching, Shelter Capacity, Microchip Lookup
Admin Service → Analytics, Triage Queues, Dashboard Data
Mesh Network Service → Node Pairing, Packet Relay, Location Sync
Notification Service → Alert Delivery, Channel Selection, Escalation
```

#### API Design
- RESTful for CRUD, gRPC for real-time communication
- Versioning: /v1/, /v2/, etc. with deprecation timelines
- Rate limiting: 100 req/s per user (burst 200), 10K req/s per service
- Error codes: Standard HTTP + custom domain codes (e.g., 400-LOCATION-GRANULARITY-INVALID)
- Audit logging: Every mutation logged with actor, timestamp, old/new values

#### Scalability Targets
- 50M users, 1M concurrent during major event
- 10M help requests/month, p95 response time <2s
- 100K groups, 5M messages/day, search latency p95 <1s
- Mesh relay: 1000s of nodes, packet drop <1%, latency <500ms end-to-end

#### Availability Targets
- Public API: 99.5% (1 hour downtime/month acceptable during disaster)
- EMS/Admin: 99.9% (5 minutes downtime/month)
- Mesh network: 95% average connectivity (graceful degradation, no critical functions offline-only)

#### Latency Targets
- Account operations: p95 <1s

- Location update: p95 <5s
- Map tile delivery: p95 <200ms

#### Data Durability
- Write replication: 3x (primary + 2 replicas across AZs)
- Backup: Daily snapshots retained 30 days, weekly retained 1 year
- Point-in-time recovery: 7 days
- Disaster recovery: RTO 4 hours, RPO 1 hour

#### Monitoring & Alerting
- Application metrics: Datadog APM (response time, error rate, CPU, memory)
- Business metrics: Help request acceptance rate, group growth, user retention
- Alerting: Pagerduty escalation (5 min critical, 15 min high, 1 hour medium)

### 4. Security, Legal & Compliance

#### Regulatory Compliance
- **CCPA:** Location data classification, user rights (access, delete, opt-out), privacy notice
- **HIPAA:** N/A (medical data not stored), but hospital reps may need business associate agreement
- **ADA:** All UI components WCAG 2.2 AA compliant, accessibility testing quarterly
- **Good Samaritan:** Legal review of help request liability waivers, insurance rider for volunteer coordinator role
- **Child Safety (COPPA):** Under 13 requires parental consent, no direct contact features for minors
- **CMMC Level 2:** Encryption, MFA, incident response, 110 practices from NIST SP 800-171

#### Data Governance
- **PII Handling:** Minimize storage (phone hashed in production), encrypt at rest, no third-party sharing without explicit consent
- **Location Data:** Most sensitive asset, encrypted end-to-end for group sharing, EMSonly request requires user consent + audit log
- **Retention:** Location 30 days post-event, help requests 6 months, user profiles indefinite (unless deleted)
- **User Rights:** Export, delete, rectification, portability (via admin API)

#### Incident Response
- **Detection:** Automated alerting for unauthorized access, data exfiltration attempts, >0.1% error rate
- **Response:** 15-minute escalation, 60-minute containment SLA, 4-hour customer notification
- **Forensics:** VPC Flow Logs, database audit logs, mesh network packet capture (48-hour retention)
- **Communication:** Legal + incident commander + customers, coordinated public disclosure if >1000 users affected

#### Cryptography
- **Key Management:** AWS KMS, customer-managed keys, quarterly rotation
- **Encryption Algorithms:** AES-256-GCM (symmetric), RSA-2048 (asymmetric for key exchange)
- **Session Management:** JWT with RS256 signature, 15-minute expiration, refresh tokens 24 hours
- **Message Signing:** HMAC-SHA256 for group messages (non-repudiation), ECDSA P-384 for mesh packets

### 5. Mesh & Network

#### Offline-First Architecture
- **User Profile:** Cached locally (100MB), synced on reconnect
- **Groups & Messages:** Last 24 hours cached (500MB), CRDT conflict resolution
- **Location Sharing:** Queued locally, broadcast on mesh or cellular reconnect
- **Help Requests:** Open requests cached, accept/decline actions queued
- **Animal Rescues:** Reports cached, photos synced when bandwidth available

#### Mesh Network Integration
- **Node Discovery:** BLE scanning + WiFi SSIDs for local network detection
- **Routing:** OLSR (Optimized Link State Routing), 3-hop max for flood messages
- **Encryption:** ECDH P-256 key exchange on pairing, AES-256-GCM session
- **Relay Capacity:** Mobile device can relay for 100s of neighbors, degrades gracefully if battery <20%

#### Offline Capabilities
- Map view (cached tiles, hazard layer from last sync)
- Help request broadcast (via mesh flooding)
- Location reporting (queued, synced on reconnect)
- Group messaging (queued, synced on reconnect)
- Animal rescue requests (submitted via mesh)

### Account Management Schema for Admin Use

**Admin-Specific Views (Read-Only):**
```sql
-- Verification review queue
CREATE VIEW verification_queue AS
SELECT
  u.id, u.email, u.display_name,
  u.id_verification_status, u.id_verified_at,
  u.sex_offender_check_status, u.sex_offender_last_checked,
  u.updated_at
FROM users u
WHERE u.id_verified_at IS NULL OR
      u.id_verification_status = 'flagged' OR
      u.sex_offender_check_status = 'flagged'
ORDER BY u.created_at ASC;

-- Active help requests by status
CREATE VIEW help_requests_active AS
SELECT
  hr.id, hr.created_at, u.display_name,
  hr.category, hr.urgency, hr.status,
  COUNT(DISTINCT hr.responder_ids) as responder_count,
  hr.expires_at
FROM help_requests hr
JOIN users u ON hr.user_id = u.id
WHERE hr.status IN ('open', 'accepted', 'in_progress')
GROUP BY hr.id, u.id
ORDER BY hr.urgency DESC, hr.created_at ASC;

-- Group health metrics
CREATE VIEW group_health AS
SELECT
  g.id, g.type, g.name, COUNT(DISTINCT gm.user_id) as member_count,
  COUNT(DISTINCT gm2.user_id) as active_members_30d,
  MAX(gm2.joined_at) as last_activity,
  CASE WHEN u.updated_at < NOW() - INTERVAL '180 days' THEN 'dormant' ELSE 'active' END as status
FROM groups g
LEFT JOIN group_members gm ON g.id = gm.group_id
LEFT JOIN group_members gm2 ON g.id = gm2.group_id AND gm2.joined_at > NOW() - INTERVAL '30 days'
LEFT JOIN users u ON g.founder_id = u.id
GROUP BY g.id, u.id
ORDER BY last_activity DESC;
```

### Platform-Specific Notes

#### iOS (React Native)
- Use native CLLocationManager for GPS (higher accuracy than WebView)
- Handle background location updates (ask user for "Always" permission)
- Apple Health integration for medical info (if user shared)
- Siri shortcuts for emergency broadcasts

#### Android
- Use Android Location API + Google Play Services
- Handle Doze mode (location updates suspended, users notified)
- Request FOREGROUND_SERVICE permission for mesh network
- Material Design 3 compatibility (though Beacon uses custom Inter font)

#### Offline & Mesh
- Cache map tiles (500MB priority: user location + 10km radius)
- Sync strategy: CRDT for messages (last-write-wins on responder list)
- Mesh relay: background service, user can disable in settings
- Battery saver: switch to 60-min location frequency if <20% battery

## Conclusion

The People & Community module forms the human foundation of Beacon. By combining verified identity, trusted communities, and peer-to-peer coordination, it enables both proactive connection (daily neighborhood engagement) and reactive emergency response (evacuation logistics, mutual aid dispatch).

**Key Success Factors:**
1. **Trust:** Transparent vetting, clear liability boundaries, Good Samaritan protection
2. **Usability:** <2 min to set up account, obvious paths to create/join groups
3. **Safety:** Background checks, responder feedback loops, animal welfare validation
4. **Resilience:** Offline-first mesh network, location sharing privacy controls
5. **Scalability:** Geohashing for group discovery, CRDT for offline sync, async background checks
