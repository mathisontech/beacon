# Public Groups

## Overview

Public groups organize users by shared geography or community context. Groups enable coordination, information sharing, and evacuation logistics. Beacon supports four primary group types, each with distinct governance and operational characteristics.

## Group Types

### Neighborhood Groups

Neighborhood groups form geographic clusters, typically 50-500 households in a defined area. Membership is discovery-based: users see available groups near their home location. Boundaries derive from census tract data, fire district boundaries, or manually drawn service areas.

Formation: Users can create neighborhood groups by selecting area boundaries. Groups become discoverable when 10+ active members join. Founding member becomes default admin until transfer.

Admin privileges: Add/remove members, set group policies, enable/disable location sharing within group, manage group messaging channels, delete group (if ≤20 members and inactive >90 days).

### Parent-Community Groups

Schools and education facilities spawn parent-community groups automatically via partnership integrations. School principal receives admin invite; parents auto-discover groups tied to their children's school enrollment.

Membership verification: Email domain matching (@district.edu) or manual principal approval. Staff members (principal, counselors) have elevated permissions: view child's location during events, receive school-specific evacuation broadcasts.

Messaging: Dedicated channels for emergency updates, daily weather briefings, evacuation status, resource requests.

### Burn-Together Groups

Auto-calculated groups formed algorithmically for prescribed burn coordination. System analyzes wind direction, fuel moisture, vegetation flammability index, and proximity to create optimal burn teams.

Criteria: Within 5-mile radius, similar fuel type (chaparral, grassland, forest), prevailing wind within 30-degree corridor, property owners within same insurance risk tier.

Admin coordination: Fire chief or designated burn coordinator oversees group. Can manually adjust AI-suggested membership. Group dissolves after burn completion or 180-day expiration.

### Evacuation Convoy Groups

Temporary groups formed during active evacuations. Generated by evacuation system (Section 12) based on shelter assignments, route clustering, and resource availability.

Properties: Time-limited (active only during event), read-only for members, driver and passengers pre-assigned with roles, vehicle capacity tracked, departure/arrival reporting.

Coordination: Members receive real-time convoy status, vehicle position (neighborhood-granule only), checkpoint arrival timestamps, communication to shelter operations.

## Privacy Controls

All groups support three location-sharing modes:

- **Off:** No location visible to other members. Enables participation in messaging/logistics without tracking.
- **Group-only:** Location visible within group, granularity selected per user (exact, neighborhood-block, neighborhood-level, city-level).
- **Periodic:** Location updates only when member initiates check-in, visible for 2 hours then auto-expires.

Members can toggle modes independently. Location data encrypted end-to-end within group. No location history stored longer than 72 hours.

Privacy audit: Members see list of who accessed their location, timestamps, frequency. Can revoke access retroactively.

## Admin Roles and Permissions

### Founder
- Create group, set name/description, select group type
- Approve/remove members (for private groups)
- Transfer founder role to another member
- View group analytics: member count, active sessions, message volume
- Cannot delete own account without transferring founder status

### Admin (delegated)
- All founder permissions except founder transfer
- Manage sub-admins (appoint/revoke, but not founder)
- Set group policies: location sharing defaults, messaging rules, event protocols
- Schedule group broadcasts and notifications
- View member details (name, profile, join date, activity level)

### Moderator
- Remove members and messages (flagged or off-policy)
- Pin announcements
- Create public/restricted channels
- View moderation queue and member reports
- No admin role transfer or policy changes

### Member
- View group directory (name, approximate location if shared)
- Send/receive messages in available channels
- Join evacuation convoys and events
- Update own location sharing settings
- Leave group anytime

## Evacuation Coordination

Groups act as coordination hubs during active events (watch/warning/emergency phases).

Activation: When evacuation alert triggers for area containing group members, group automatically enters "event mode" and displays:
- Evacuation zone map overlay
- Shelter assignments and directions
- Convoy signup and roster
- Estimated capacity, open spots per shelter
- Resource needs (medical, elderly transport, pet-friendly)

Member actions: Join convoy, confirm household evacuation status, report vulnerable members needing assistance, request resource (wheelchair accessible shelter, medication availability, language support).

Tracking: Admins see real-time departure confirmation, shelter arrival timestamps, unaccounted members (non-responsive for >30 min after evacuation order). Push notifications to non-responding members with increasing frequency.

Communication: Pre-composed templates for common messages ("leaving now," "sheltering in place," "returning home"). Group broadcasts logged and searchable post-event for after-action review.

## Group Data Lifecycle

Creation to Dissolution:
- Active groups (≥1 post/week, ≥50% member monthly active): indefinite
- Dormant groups (no activity >90 days): marked inactive, members notified. Auto-deleted after 180 days unless activity resumes.
- Event groups (evacuation, burn): auto-expire 30 days post-event, data archived for 1 year.
- Deleted groups: member list and location data purged immediately; messages exported to admins (if requested), then deleted.

Founder succession: If founder inactive >180 days, system prompts senior admin to assume founder role. If no active admins, group enters dormant state and eventually archives.

## Implementation Notes

Database schema: Groups table (id, type, name, created_by, geometry, privacy_tier), Members table (group_id, user_id, role, location_share_mode, joined_at), Messages table (group_id, author_id, channel, text, timestamp, encrypted_location_blob).

Location sharing: Polygon-based granularity stored server-side; clients request location as coarse/fine based on user setting. Fine requests logged and audited.

Mesh network support: Group roster cached locally on user device; messages sync via mesh when offline, conflicts resolved by timestamp + deterministic ordering.

Scale: Beacon targets 1M neighborhood groups (avg 200 members), 50K school groups (avg 150 members), 10K burn-together groups (seasonal, avg 8 members), 10K concurrent evacuation groups (avg 30 members).
