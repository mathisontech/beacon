## Module Descriptions

### 10_global_fallback/ (3 files, 365 lines)

Global base map FALLBACK system for areas outside US, rural regions, and ocean areas.

| File | Lines | Content |
|------|-------|---------|
| 00_global_fallback_overview | 89 | Fallback data sources, available attributes, confidence tiers, accuracy degradation |
| 01_global_pipeline_layers | 111 | Processing specs per global source, functions table, storage, SLA, cost model |
| 02_fallback_confidence_scoring | 165 | Coverage assessment functions, tier classification, downstream impact, gap reporting |

**Key Concepts:**
- Lower confidence (0.2-0.5 vs 0.7-0.9 for full coverage)
- Tiles flagged for fallback status
- Confidence-scaled uncertainty for downstream hazard models
- Data acquisition prioritization by population density

### 11_update_protocols/ (4 files, 707 lines)

Three update triggers: scheduled source refresh, post-event resurvey, user-reported changes.

| File | Lines | Content |
|------|-------|---------|
| 00_update_overview | 134 | Update triggers, pipeline stages, ownership, version control, conflict resolution |
| 01_source_refresh_protocol | 161 | Scheduled data ingestion, alignment, extraction, validation, promotion, archive |
| 02_post_event_update_protocol | 182 | Event-triggered resurvey, satellite/aerial tasking, damage assessment, expedited promotion |
| 03_user_reported_changes | 230 | Street-level perception, change classification, persistent vs transient, rewards |

**Key Concepts:**
- Post-event SLA: first update within 6 hours
- Persistent vs transient: persistent updates versioned, transient updates routing-only
- Multi-modal change detection: optical flow + CNN + geolocation
- Confidence thresholds, deduplication, manual review queue

### 12_tile_delivery/ (4 files, 1,042 lines)

PMTiles format, 1km grid, CloudFront CDN, offline 5GB LRU cache.

| File | Lines | Content |
|------|-------|---------|
| 00_tile_delivery_overview | 208 | Architecture, PMTiles format, compression, delta encoding, CDN, offline cache, cost |
| 01_tile_generation | 296 | Compose, index, hash, compress, generate PMTiles, deltas, validate, processing load |
| 02_cdn_distribution | 253 | CloudFront config, range requests, cache mgmt, origin failover, monitoring |
| 03_offline_cache | 285 | 5GB LRU cache, precaching saved locations + hazards, sync protocols, mesh |

**Key Concepts:**
- Tile fetch SLA: <50ms p95 (CDN), <60 sec startup sync
- Range requests enable single-feature fetch (99.9% bandwidth savings)
- Delta tiles (~50KB) vs full tiles (~1MB) for updates
- Mesh network propagation reduces CDN bandwidth for local clusters

### 13_digital_twin/ (2 files, 646 lines)

Persistent, updateable model of Earth's surface. Single source of truth, immutable snapshots, rollback capable.

| File | Lines | Content |
|------|-------|---------|
| 00_digital_twin_overview | 234 | Architecture, data flow, storage (PostgreSQL, TimescaleDB, S3, Redis), consumers, retention |
| 01_twin_state_management | 412 | Functions for state ops, initialization, apply updates, versioning, rollback, queries |

**Key Concepts:**
- Version snapshots: immutable checkpoints, rollback to any prior version <30 min
- Real-time updates: <1 min latency for user reports, <5 min for street-level
- Storage: hot (PostgreSQL), warm (S3), cold (Glacier) with tiered retention
- Time-series tracking: 5-year history per attribute change

## Style and Content

**Minimal Text Approach:**
- Tables for structured data (functions, costs, metrics, SLA)
- Short descriptions (1-2 sentences per concept)
- Code blocks for algorithms and data structures
- No emojis or icons

**Template Compliance:**
Each file includes:
1. Functions table (input, output, role, SLA)
2. Data storage specifications
3. NATS topics for real-time messaging
4. Redis cache patterns (where applicable)
5. Cost models and infrastructure
6. Monitoring and health metrics
7. Accuracy targets and confidence thresholds

**Cross-Module Integration:**
- Fallback system feeds global pipeline
- Updates trigger tile generation and CDN invalidation
- Digital twin receives updates from all sources
- Tiles delivered via CDN to clients with offline cache
- NATS broadcasts propagate state changes to downstream consumers
